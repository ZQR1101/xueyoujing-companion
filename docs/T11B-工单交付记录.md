## 二、后端流程（与规划书 T11-B 固定流程一一对应）

```text
读取学习状态(planner._classify + mastery) → 规则生成候选(build_candidates)
→ 调用 LLM(gateway.decide) → Schema 校验 → 校验 action/target/evidence 归属
→ 执行合法行动(规则执行器 _execute) → 写入决策轨迹(PathDecision)
→ 必要时生成新 Plan.version（仅任务集合真实变化时）
```

### 候选行动（全部由规则层生成，LLM 不得追加）

优先级即 §9.2：`schedule_review`（复习到期）→ `insert_probe`（同概念 ≥2 道不同题错误、
无排队练习、预算足够）→ `continue_task`（计划下一任务）。候选为空返回
`no_legal_action`，不伪造任务。

### 结构化返回（含 T11-F 所需字段）

`candidate_actions / selected_action / reason / evidence_ids / policy_version / model_id /
planner_source / fallback_reason / duration_ms / plan_before / plan_after（路径调整前后）/
changed / current_task（当前任务）/ input_state_hash（重放依据）`。

## 三、数据与安全约束的落实

| 规划书约束 | 落实 |
|---|---|
| candidate_actions 由规则层生成 | 生成器纯规则实现；LLM payload 中的 legal_actions 即该集合 |
| target/evidence/concept 存在且归属当前学生 | `_validate_parsed` 按 action+target_id 精确匹配候选；Evidence 逐条归属校验 |
| 先修/预算/复习优先级/权限在模型调用前后执行 | 候选生成即规则校验（含预算与去重）；执行器再校验（task_owned）；路由层 goal_owned + expected_version 409 |
| 不允许模型直接写掌握度/解锁/删任务 | 执行器只有两种合法动作：读取型行动（无写）与 insert_probe（规则代码补一道练习任务并升版） |
| 路径无实际变化不升 Plan.version | continue_task / schedule_review → changed=False 版本不变（A07 复测通过） |
| 相同输入支持决策重放 | `input_state_hash = sha256(规则版本+计划版本+掌握签名+候选集合)`，同输入同哈希（测试验证） |
| 决策记录保存候选/选择/理由/证据/规则版本/模型来源/耗时/回退原因 | PathDecision 全字段持久化，GET 列表可查询 |
| 非法 JSON 修复一次；超时/伪造 → 规则首选 + rule_fallback | 与 coordinator 同款网关语义；测试覆盖伪造 target、非法 JSON、超时三场景 |
| 候选为空 → no_legal_action 不伪造 | 测试验证（尚无计划时） |
| 版本冲突返回最新计划不覆盖 | expected_version 不匹配 → 409 version_conflict，消息带当前版本号 |

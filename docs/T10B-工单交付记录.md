## 二、接口与 Schema（API 合同增补，详见 docs/API合同_增补_T10-T11.md）

- `POST /api/v1/goals/{goal_id}/diagnosis-report`（幂等）：生成并持久化诊断。
- `GET /api/v1/goals/{goal_id}/diagnosis-report`：最近一次诊断（只读，无则 404）。
- 返回结构化结果至少含：`observations / hypotheses / recommended_probe / evidence_ids`
  （规划书 T10-B 要求），外加 `summary / status / planner_source / model_id / fallback_reason /
  state（掌握与证据计数）/ policy_version / duration_ms`。

## 三、安全与语义约束的落实

| 约束 | 落实 |
|---|---|
| evidence_id / concept_id 归属与存在性校验 | `_validate_parsed`：concept_id 必须在目标课程集合内；evidence_id 必须真实属于当前学生；违规记 `fabricated_*` |
| 模型失败/超时/非法 JSON/虚构 ID/证据不足 → 可解释规则回退 | 证据不足不调模型直接规则结果；JSON 与校验失败修复一次后回退；超时直接回退；全部标记 `rule_fallback` + `fallback_reason`，不阻塞学习（HTTP 200） |
| AI 诊断与确定性评分分开保存 | 只写 `diagnosis_reports` / `llm_usage`，不触碰 MasteryState/Evidence（测试断言生成前后 mastery 不变） |
| 不泄露私有内容 | 输入 payload 只含公开字段（概念状态/估计/证据计数/家族 ID/对错），不含答案、提示、prompt 原文 |
| 学生视图不得见模型原始输出 | 返回仅结构化字段，不返回 token/原始文本/内部日志 |

## 四、五场景验收（tests/test_t10b_diagnosis_report.py）

| 场景 | 结果 |
|---|---|
| 证据不足 | 不调用模型（用哨兵 provider 断言零调用），返回 `insufficient_evidence` 规则结果 |
| 正常 | ScriptedProvider 合法 JSON → `planner_source=llm`，结构化字段入库，掌握度不变 |
| 无思路（空诊断） | 合法 JSON 但 observations/hypotheses 全空 → `empty_diagnosis` 修复一次 → 规则回退 |
| 虚构 ID | concept_id=C99 → 修复一次仍虚构 → `fabricated_concept_id` 回退，规则结果非空可用 |
| 非法 JSON / 超时 | 修复一次仍失败 / TimeoutProvider → 回退且 `fallback_reason` 含原因 |

另有：诊断记录与用量分开持久化（llm_usage.purpose=diagnosis_report）、学生 B 访问 404 无泄露。

## 4. 核心用户流程

### 4.1 首次进入

选择专题与目标 → 设置每日时长 → 开始诊断 → 完成最多 6 道初筛题 → 查看已测与未测知识点 → 确认学习安排 → 进入首个任务。

诊断不得根据少量题目断言整个专题掌握程度；未测试的知识点显示“尚未评估”。允许跳过或中断，跳过不算答错，刷新后继续。

### 4.2 日常学习

打开今日任务 → 阅读讲解或短例题 → 独立练习 → 若答错则追问与提示 → 原题重试 → 新题独立验证 → 更新证据与下一步任务 → 查看小结。

原题提示后答对表示“在帮助下完成”，新题独立答对才提供新的掌握证据。

### 4.3 再次进入

读取相同学生的历史和当前任务 → 显示上次停留位置 → 根据复习到期和近期表现推荐继续或复习。学生身份跨会话保持一致；不同学生的数据相互隔离。

                         ├─ 诊断与确定性评分
                         ├─ 掌握状态投影
                         ├─ 路径候选生成与校验

## 7. 掌握度策略 v1

### 7.1 有效证据

有效证据必须来自已核验题目的确定性评分，且是该 Exercise 第一次作答、无提示、未看答案。每个学生在每个 `family_id` 最多贡献一份掌握证据；相似参数题共用 family，以免反复刷分。

错误也属于有效证据。提示后的完成、原题重做、阅读内容、跳过和无法确定的评分均不进入掌握数值，但保留用于辅导与完成情况展示。

### 7.2 可重复计算公式

对一个知识点，取最近最多 8 份不同 family 的有效证据，正确记 1，错误记 0：

```text
n = 有效证据数
estimate = null                         当 n = 0
estimate = (1 + sum(scores)) / (2 + n)   当 n > 0
evidence_strength = min(n / 5, 1)
```

`evidence_strength` 仅表示证据数量充足程度，不是统计置信区间或模型准确率。该平滑规则是工程基线，不宣称为经校准的知识追踪模型。

状态判定顺序：

1. n=0：`unassessed`。
2. n≥3、estimate≥0.8、最近两份证据均正确：`mastered`。
3. n≥2、estimate<0.5：`needs_support`。
4. 其他：`developing`。

示例：三份独立正确证据得到 4/5=0.8；两错得到 1/4=0.25；错一次后提示答对原题，仍为 1/3。不得为了演示而在前端加分。

复习到期单独记录 `review_due_at`。时间经过不自动降低掌握估计；到期只是安排复测。首版采用完成后 1 天的固定复习间隔，并明确是可配置基线。

### 7.3 历史与纠正

每次有效证据提交后保存 before/after 快照，包含公式版本和证据 ID。回放相同事件应得到相同结果。撤回无效证据后重新计算，不执行反向减分补丁。

## 8. 诊断与课程包

示例课程依赖：

```text
C01 平方与代入 → C02 函数输入输出 → C03 二次函数图像
                                  C03 → C04 顶点式
                                  C03 → C05 开口与对称轴
                                  C04 + C05 → C06 简单应用
```

课程作者需核验依赖和题目与知识点的映射，此图是首版组织方案。每个知识点至少 4 个不同题族，覆盖初筛、练习、迁移和复习用途。需要 3 份正确证据才能达到掌握门槛，因此不得只准备一道题反复演示。

首轮诊断最多 6 题，每个目标范围内知识点优先覆盖一题，顺序按拓扑稳定排列。初筛结果仅用于确定入口；不足以判定掌握时显示证据不足，并在学习中补测。题库耗尽时返回 `insufficient_items`，保留现有估计，不能临时生成未经核验题后计入正式掌握分数。

首版评分只支持选择题和有限数值输入。数值规范化规则随题配置：允许空格、正负号、约分后的有理数或容差明确的小数；禁止用 eval 执行学生输入。开放式解题过程可由 LLM 分析并追问，但首版不自动进入正式掌握度。

## 9. 自适应路径决策

### 9.1 长期路径与短期行动

长期路径是目标及前置知识点的有序集合；短期行动是此刻选择哪项讲解、练习或复习。不要用一次 LLM 文本回答同时代表两者。

先由规则产生合法行动，再由 LLM 在合法范围内选择。LLM 可结合学生表达的困惑决定先举例、先追问或继续练习；规则负责知识点 ID、依赖、预算和证据有效性。

### 9.2 默认排序规则

1. 先恢复已有未完成 Exercise，避免换题丢失过程。
2. 已到期复习优先于新内容。
3. 目标范围内未掌握的最早前置知识点优先。
4. 同一拓扑层：有重复错误者优先，再按低 estimate、稳定 concept_id 排序；未评估者进入诊断补测。
5. 当前节点完成且所有前置节点 mastered，才解锁后继正式任务；允许预览，预览不计掌握。
6. 预算不够时保留合法前缀，并显示剩余任务；不得绕过前置约束塞入后继节点。

默认任务用时：lesson 5 分钟、practice 5 分钟、transfer 5 分钟、review 5 分钟。预计时长总和不得超过 daily_minutes，首版不强制凑满 3～5 个任务。

### 9.3 重规划触发与版本

有效证据改变、复习到期、目标/时长更新、同类错误出现在两道不同题、学生明确请求调整时重算候选。只有路径顺序、任务集合或节点状态真正改变才增加 Plan.version；普通聊天和无变化评估不产生新版本。

单次作答最多触发一次自动规划。已完成任务保持不变，当前 Exercise 保留，其余待办可调整。记录 before/after、reason_code 和 evidence_ids。重复错误的统计不能把同一道题的多次重试算成两题。

### 9.4 LLM 决策合同

```json
{
  "action": "offer_hint",
  "target_id": "existing-exercise-id",
  "reason_code": "repeated_error",
  "evidence_ids": ["existing-event-id"],
  "student_message": "我们先检查括号里的符号。"
}
```

action 限定为 `ask_clarification / present_lesson / assign_practice / offer_hint / assign_transfer / schedule_review / finish_session`。校验 target 归属、阶段合法性和证据引用。不得请求模型输出隐藏思维链；展示简短决策依据和工具轨迹即可。

结构化输出失败最多修复一次，再使用规则回退。模型可用时必须真实参与至少一次教学行动选择，并记录 planner_source=`llm`；离线回退必须标记 `rule_fallback`，不能拿纯规则演示伪装在线 Agent。

## 10. 脚手架辅导与状态机

Session 状态：`diagnosing / ready / learning / paused / completed`。Exercise 状态单独管理，不用一串全局状态承载所有页面逻辑。

| 当前场景 | 事件 | 处理 | 后续 |
|---|---|---|---|
| diagnosing | 提交答案 | 确定性评分、写证据 | 下一诊断题或 ready |
| ready | 开始任务 | 创建/恢复任务 Exercise | learning |
| learning | 首次答错 | 记录证据、邀请说明思路 | 保持 Exercise open |
| learning | 请求提示 | 只返回下一层提示 | hint_level 增加 |
| learning | 原题答对 | 关闭 Exercise | 安排新 family 迁移题 |
| learning | 迁移题完成 | 更新证据、评估路径 | 继续任务或小结 |
| 任意进行中 | 暂停 | 保存位置 | paused |
| paused | 恢复 | 根据保存上下文恢复 | diagnosing/ready/learning |

提示分级：0 无提示；1 提醒概念；2 指出关键关系；3 用不同数字的类比；4 提供下一步局部过程。默认第一轮错误只给反馈和追问，不自动倾倒全部提示。连续请求提示可以逐级推进，每次只返回一层。

学生明确选择“查看解析”时，允许返回完整解答，设置 solution_seen=true；后续原题不产生独立掌握证据，必须给新题验证。不要无限追问或强迫学生完成。

首版采用课程包内核验提示。LLM 可根据错误类型选择合法提示或补充追问；无法保证自由生成提示绝不泄露答案，因此答题前的提示展示优先用核验内容。所有题型必须检查网络响应，不只是检查界面是否隐藏答案。

## 11. 记忆与一致性

SQLite 是唯一事实源。L1 为学习事件，L2 为有证据的事实，L3 为可重建的画像投影；不再额外维护与 SQLite 双写的 JSONL 主存储。

最小事件集合：`goal_created / diagnosis_started / answer_submitted / answer_graded / hint_shown / solution_viewed / mastery_updated / plan_changed / task_completed / session_paused / reflection_saved`。

一次成功作答提交应在同一短事务中写入 Attempt、评分结果、Evidence、MasteryState、相应事件与幂等响应。外部 LLM 调用在事务外完成；提交时检查版本，过期结果不得覆盖新状态。

自然语言总结不是阻塞条件。确定性状态先提交，LLM 总结失败则返回规则说明并允许后续重试。首版不依赖额外队列服务。

记忆输入包括当前目标、当前任务、近期最多 8 份相关证据、相关错误和学生明确表达的偏好；不把全部聊天无限塞入 Prompt。偏好是可修改选择，不是固定学习风格标签。

所有写请求提供 `Idempotency-Key`。作用域为学生+方法+规范路径+键：同键同载荷返回首次响应，同键不同载荷返回 409；即使响应丢失也不得重复加证据、升级提示或创建任务。

```json
{
  "data": {},
  "next_action": {"type": "retry_exercise", "target_id": "exercise-id"},
  "resource_version": 4,
  "trace_id": "trace-id"
}
```

next_action 可空；resource_version 对应本接口主要资源，并在 DTO 中返回关联 Session/Exercise 的各自版本，禁止混用全局与实体版本。

错误格式：`{"error":{"code":"version_conflict","message":"学习状态已更新，请刷新后继续"},"trace_id":"..."}`。400 非法操作，404 不存在或不属于当前学生，409 版本/幂等冲突，422 输入格式错误，503 模型不可用且无可用回退。

## 18. 演示与计划书

5分钟推荐顺序：

1. 30秒：首次诊断，展示未测范围和推荐入口。
2. 45秒：并排展示两个演示学生的不同路径，说明来自不同答题证据。
3. 90秒：一道题答错、追问、两级提示、原题完成，显示“在帮助下完成”。
4. 60秒：新题独立完成，展示证据变化与合法路径调整。为达到门槛可使用预先存在的其他独立证据，但必须标记历史演示记录。
5. 30秒：刷新页面恢复当前进度，展示记忆连续性。
6. 45秒：打开决策依据，展示一次在线LLM行动、检索引用和路径版本差异。

种子使用虚构学生，只通过演示初始化脚本导入。时间线和计算走真实后端；不得用硬编码“演示按钮”直接把掌握度改成80%。离线模式可演练，但必须可见地标记模拟模型。

计划书技术表述可采用：

> 系统将学习目标、知识前置关系与可追溯答题证据组合成持续更新的学习状态，在受约束的行动范围内由大模型选择讲解、追问、提示或练习。每次独立练习反馈会驱动掌握估计与后续任务调整，跨会话记忆保留学习依据和未完成进度，使推荐原因与辅导过程可被检查。

应用价值以单专题课后自主学习作为试点。成本按实际LLM调用次数、输入输出用量和配置价格估算；不在文档中预设未经测量的每生费用。未来教师审核题库与查看班级共性薄弱点，可作为独立扩展。

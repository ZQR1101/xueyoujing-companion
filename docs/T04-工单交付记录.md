## 四、设计说明与合同备注

1. **跳过语义（合同补充）**：§12 无"跳过当前题"端点。最小实现：`GET /assessments/{id}?after_exercise_id=X` 返回其后第一个未答题（纯读，无写入）。**建议修订**：合同增补该 query 参数或独立 skip 端点。
2. **next_action 取值（合同补充）**：合同只给了 `retry_exercise` 示例。T04 使用 `next_question` / `complete_assessment`（T06 将增补提示/迁移类取值）。**建议修订**：在合同中枚举 next_action.type 词汇表。
3. **complete 的 expected_version**：指 Assessment 当前版本；作答会同时升 Exercise/Assessment/Session 三者版本，作答响应 DTO 已按合同返回 `versions.{exercise,assessment,session}`，客户端据此前取。
4. **计划种子**：/complete 返回的 plan 为 `policy_version=v0-seed`（拓扑排序目标概念），满足合同形状；前置约束、预算、Plan.version 升版规则在 T05 实现，不视为静默重构。
5. **诊断续答**：会话已有 in_progress 评估时再调 POST diagnosis 幂等返回现有评估与第一个未答题（§4.1 刷新继续）。
6. **无效证据**：不删除、不倒扣——Evidence 行保留并标记 eligible=false 与 exclusion_reason（not_first_attempt / hint_used / solution_seen / family_already_counted）；掌握投影只统计 eligible 证据（§7.3）。
7. **家族去重兜底**：应用层检查 + SQLite 部分唯一索引（`ux_evidence_student_family_eligible WHERE eligible=1`）双保险。
8. **练习归属约束**：Exercise 表 CHECK 约束强制 task/assessment 二选一（§6"必须且只能属于其一"）。

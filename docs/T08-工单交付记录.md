## 二、需求落实对照

| 需求 | 落实 |
|---|---|
| 统一 _1 顶栏 | TopBar 组件全页共用（品牌 + 四导航 + 课程章 + 学生章），active 态随路由 |
| 修复图片 URL 当文字 | 参考稿 _2/_3/_5 顶部的裸 URL 为 stitch 导出残片；实现中无任何图片 URL 渲染，问题不复存在 |
| _1/_2 同一工作台两态 | WorkbenchPage 单页面：无任务→开始；讲解任务（R7 presented→acknowledge）；练习作答反馈态（_1）与练习作答态（_2）按后端业务状态切换 |
| 学情页空/数据条件渲染 | 无 goals → 诊断引导空态；有 goals → 覆盖率/掌握概览/近期动态（_4 两态） |
| 全部真实后端数据 | 掌握度/证据数/状态 ← /me/overview；任务解锁与推荐原因 ← /goals/{id}/path 节点 reason + plan.reason_code；掌握变化 ← /me/mastery-history；伴学回复 ← /messages 决策；未评估显示「—」不画 0 分 |

| 删除未经测量的能力文案 | 不渲染「节奏平稳/专注度高/能力天赋」类措辞；只呈现 estimate、evidence_count、status 与规划器 reason；明确「自适应诊断不含成绩」 |

## 五、说明与备注

1. 演示身份固定名「李同学」，顶栏学生章点击可切换新身份（completed 会话为终态，验收多流程时使用）。
2. 会话 completed（R8）后工作台发起任务会提示「会话已结束」——真实业务状态，前端如实呈现；切换身份即可重新开始。
3. 近期学习动态、任务解锁原因、推荐理由全部来自后端字段；无任何前端造数。
4. 诊断裂点续答（刷新后回到当前题）由 GET /sessions resumable 支持；R2 跳过为纯读接口。
